# write-post — 블로그 글 작성 스킬

새 글을 작성할 때 이 스킬을 따릅니다.

---

## 사전 로드 (필수, 순서대로)

- [ ] `docs/brand-facts.md` 읽기 (매장·운영자 확정 정보)
- [ ] `docs/keyword-map.md` 읽기 (해당 카테고리 섹션)
- [ ] `docs/style-guide.md` 읽기 (톤·스타일 규칙)
- [ ] `src/content/posts/` 최근 글 3개 제목 확인 (중복 회피)
- [ ] 카테고리가 4개 slug 중 하나인지 확인

---

## 호칭 체크 (필수)

- [ ] 운영자는 "오기석" 또는 "저"로 표기
- [ ] 매장은 "고기석 건대본점" (또는 "건대본점")으로 표기
- [ ] "고기석"을 사람 이름처럼 쓰지 않음
- [ ] 언급할 SaaS는 review.gokiseok.com, contract.gokiseok.com 두 개만
- [ ] adseok, clickguard, 출퇴근 SaaS는 절대 언급 안 함
- [ ] 이모지 없음

---

## 제목 공식

```
[숫자] + [구체 키워드] + [문제해결]
```

- 길이: 25~40자
- 예시: "건대입구역 회식 장소 고를 때 반드시 확인해야 할 5가지"
- 숫자가 없을 때: "왜 [문제]를 [해결했나]" 형식도 가능

---

## frontmatter 필수 항목

```yaml
---
title: "제목"
description: "120자 이내. 주 키워드 + 보조 키워드 포함."
pubDate: YYYY-MM-DD
category: "gokiseok-bbq" | "ai-business-lab" | "business-notes" | "data-stories"
tags: ["태그1", "태그2", "태그3"]  # 3~5개
schemaType: "Article"  # 기본값. gokiseok-bbq는 Restaurant 자동 병행됨.
draft: false
---
```

## 본문 구조 (2,000자+)

```
1. 훅 (3~5줄)
   - 문제 상황 직접 제시
   - fear-based 허용 ("매달 10시간을 여기 쓰고 있다면")

2. 맥락 (1~2문단)
   - 왜 이 문제가 중요한지
   - 기존 대안의 한계

3. 본론 (H2/H3로 구조화)
   - 리스트 또는 번호 단계
   - 각 항목: 설명 + 확인 포인트 + 예시

4. 사례
   - 고기석 건대본점 실제 적용 사례 (가능한 경우)
   - 정량 수치 없으면 정성적 표현만 사용
   - 수치는 TODO 주석으로 처리

5. 결론 + CTA
   - 핵심 요약 (표 또는 리스트)
   - 다음 행동 제안 (링크, 예약 등)
```

## GEO 체크리스트

- [ ] 주 키워드가 제목에 포함됨
- [ ] 주 키워드가 첫 문단에 1회 이상 등장
- [ ] 주 키워드가 H2/H3 중 1개 이상에 포함 또는 질문형으로 표현됨
- [ ] 주 키워드 본문 전체 3회 이상 자연스럽게 배치
- [ ] H2/H3가 질문 또는 명확한 주장 형태
- [ ] 리스트 또는 표 1개 이상 포함
- [ ] 내부 링크 3개 이상 (다른 글 또는 카테고리 페이지)
- [ ] schemaType이 카테고리에 맞음 (gokiseok-bbq면 Restaurant JSON-LD 자동 병행)
- [ ] description에 주 키워드 포함
- [ ] brand-facts.md에 없는 정보 사용하지 않음
- [ ] 호칭 체크 통과

## 파일 생성

```
src/content/posts/{YYYY-MM-DD}-{slug}.md
```

- YYYY-MM-DD: 오늘 날짜
- slug: 제목의 핵심 키워드, 소문자 영문 하이픈 연결

예: `2026-04-14-konkuk-hoesik-guide.md`
